# Matchora

Българска платформа за услуги и търсене на изпълнители. Етап 1 (P0) от спецификацията.
Стек: Next.js 15 (App Router) · TypeScript · Tailwind · PostgreSQL (`pg`) · сървърни действия.

## Какво работи
- **Акаунти:** регистрация, вход, сървърни сесии (в базата е хеш на токена), argon2id, заключване след 5 грешки, rate limiting, потвърждение на имейл и възстановяване на парола (еднократни токени). Един акаунт е клиент и/или изпълнител.
- **Услуги и търсене:** услуги с лимит от плана; търсене с full-text + trigram, синоними (ток → електро), филтри по категория, град, цена, дистанционно, проверен. Скрити са услугите на изпълнители без действащ план.
- **Абонаменти и плащания:** Start/Pro/Business; права само след подписан и идемпотентен webhook (`/api/webhooks/payments`, HMAC-SHA256); фактурни номера.
- **Кредитен ledger:** портфейл с CHECK срещу отрицателен баланс, ledger само за добавяне (тригер), идемпотентни ключове, заключване на реда при едновременни операции.
- **Matchora Bids:** оферта с кандидатстване (кредити), boost, топ слотове, ръчен и Auto Boost, равен залог печели по-ранният; при приемане победителите в слотовете се таксуват, останалите залози се освобождават; отказано задание освобождава всичко.
- **Задания, оферти, поръчки:** автоматична проверка и модерация, приемане само от собственика, поръчки със статуси, чат, известия (в приложението и по имейл), ревю само от клиент по завършена поръчка, сигнали.
- **Двуфакторна автентикация (TOTP):** QR + ръчен ключ, 10 кода за възстановяване (показват се веднъж), защита срещу повторно ползване на код, лимит на опитите. Секретите са шифровани с AES-256-GCM (`APP_SECRET`). **За персонала (admin/moderator/support) е задължителна** – без нея администрацията не се отваря.
- **Имейли:** SMTP чрез `SMTP_URL`, опашка в базата с повторни опити (2, 4, 8… мин., до 6 пъти). Повтарящата се доставка се задейства от `GET /api/cron/mail` с `Authorization: Bearer $CRON_SECRET` (на всеки 5 мин.) или от `npm run mail:flush`.
- **Плащания със Stripe:** `PAYMENT_PROVIDER=stripe` включва Checkout (единични пакети кредити и месечни абонаменти), подписан webhook `POST /api/webhooks/stripe` (идемпотентен по id на събитието, 5 мин. толеранс), подновяване и неуспешно плащане, спиране на подновяването, възстановявания и спорове (отиват за преглед в админ таблото с опция „приспадни кредитите“).
- **Реклами:** изпълнителят купува с кредити „Търсене“, „Топ в категория“ или „Начална страница“ за 1–30 дни; админ/модератор одобрява (отказът връща кредитите); рекламите са ясно означени „Спонсорирано“, ротират се справедливо, показванията и кликовете се отчитат най-много веднъж на час от зрител, ботове и собственикът не се броят. Цените и слотовете се менят от `/admin/settings`.
- **Фирмени профили:** ЕИК/БУЛСТАТ с проверка на контролната цифра (9 и 13 цифри), ДДС номер, проверка от администратор (значка „Проверена фирма“), екип по покана (имейл, 7 дни, само за поканения адрес) с права „услуги“ и „заявки“. Абонаментът, кредитите, поръчките и плащанията остават при собственика; членовете не ги виждат. Смяна на наименование или ДДС номер връща фирмата в „чака проверка“.
- **Админ:** табло и MRR, модерация, сигнали, потребители (спиране, проверка), ledger с ръчна корекция (причина + одит), настройки на Bids, одит лог. Роли: support, moderator, admin.

## Локално стартиране
Базата трябва да е UTF-8 с локал, който разпознава кирилица, иначе търсенето не работи (миграцията проверява и спира):
```sql
CREATE DATABASE matchora ENCODING 'UTF8' LC_COLLATE 'C.utf8' LC_CTYPE 'C.utf8' TEMPLATE template0;
CREATE EXTENSION pg_trgm;  -- в тази база, от суперпотребител
```
```bash
cp .env.example .env.local     # попълнете DATABASE_URL, APP_SECRET и CRON_SECRET (openssl rand -hex 32)
npm install
npm run migrate
npm run dev                    # http://localhost:3000
npm run make-staff -- you@example.com admin   # първи администратор
```

## Тестове


## Deployment (избор на собственика)
**VPS:** Node 22 + PostgreSQL 16 (UTF-8), `npm ci && npm run build && npm run migrate`, `npm start` зад nginx с HTTPS, процес под pm2/systemd.
**Vercel + управлявана Postgres:** променливите от `.env.example`, миграциите от вашия компютър.
**Задължително преди реален старт (виж и раздели 12 и 17 от спецификацията):**
1. **Плащания:** в продукция тестовото плащане е изключено. За Stripe: `PAYMENT_PROVIDER=stripe`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`; в Stripe Dashboard добавете endpoint `<APP_URL>/api/webhooks/stripe` със събития `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.expired`, `checkout.session.async_payment_failed`, `invoice.paid`, `invoice.payment_failed`, `customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`, `charge.dispute.created`. **Адаптерът е тестван само с подписани тестови събития, не срещу реален Stripe** – направете пълен тест в Stripe test mode (карта 4242…) преди да приемете пари.
2. `SMTP_URL`, `MAIL_FROM` и домейн за `APP_URL`; настройте cron към `/api/cron/mail`.
3. `APP_SECRET` (≥32 случайни символа) – задължителен в продукция; при смяна 2FA настройките се губят. `CRON_SECRET`. Първият администратор: `npm run make-staff -- имейл admin`, след това веднага включете 2FA от `/security`.
4. Общи условия, политика за поверителност, GDPR процеси, преценка за Digital Services Act, ДДС по фактурите: нужна е юридическа и счетоводна преценка.
5. Автоматичен backup, restore тест, мониторинг на грешки, cron за изтичане на абонаменти (видимостта вече зависи от `period_end`, така че изтеклите планове се скриват и без cron).
6. Rate limiting е в базата и е достатъчен за старт; при голям трафик го преместете в Redis или на ръба.

## Решения, които чакат потвърждение (раздел 22)
Работни стойности в кода: кандидатстване 10 кредита (дебитира се при подаване, не се връща при оттегляне); минимален залог 5, стъпка 1, 3 слота (променят се от админ панела); boost се таксува само за спечелена позиция при приемане; контактите остават скрити, общуването е в чата; физически лица се допускат във всички категории; плащането за услугата е извън платформата.

## Извън обхвата засега
ЕИК се проверява само по контролна цифра и от администратор ръчно (няма автоматична връзка с Търговския регистър); членовете на екипа не работят с поръчките; SMS/push, спорове с арбитраж, комисиони и escrow, AI помощник (Етап 2 и 3).

## Деплой на Vercel (стъпки)
1. **База:** създайте Postgres (напр. Neon или Supabase) в UTF-8 база; изпълнете `CREATE EXTENSION pg_trgm;`. Вземете *pooled* connection string (с `sslmode=require`). Локалът трябва да разпознава кирилица – при Neon/Supabase по подразбиране е ОК; `npm run migrate` ще спре с грешка, ако не е.
2. **Миграции от вашия компютър:** `DATABASE_URL="<url>" npm run migrate`, после `DATABASE_URL="<url>" npm run make-staff -- you@example.com admin`.
3. **Качете кода в GitHub** и в Vercel изберете *Add New → Project → Import*. Framework: Next.js (автоматично).
4. **Environment Variables** (Production): `DATABASE_URL`, `APP_URL` (https://вашият-домейн), `APP_SECRET` (`openssl rand -hex 32`), `CRON_SECRET` (`openssl rand -hex 24`), `SMTP_URL`, `MAIL_FROM`, `PAYMENT_PROVIDER=stripe`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`. Не задавайте `PAYMENT_PROVIDER=mock` в продукция.
5. **Stripe webhook:** endpoint `https://вашият-домейн/api/webhooks/stripe` (събитията са изброени по-горе).
6. **Cron за имейли:** `vercel.json` пуска `/api/cron/mail` веднъж дневно (лимит на Hobby плана; Vercel праща `Authorization: Bearer $CRON_SECRET` автоматично). Имейлите се опитват да излязат веднага, кронът е само резерва; на Pro план сменете на `*/5 * * * *`.
7. Свържете домейна от *Settings → Domains*, после влезте, включете 2FA на админа от `/security`.

### Supabase
`DATABASE_URL` за **Vercel**: Supabase → Connect → *Transaction pooler* (порт 6543), със `?sslmode=require` в края. За миграциите (GitHub Actions secret `DATABASE_URL`) ползвайте *Session pooler* (порт 5432 на pooler хоста; директната връзка е само IPv6). Паролата с специални символи се кодира в URL (напр. `@` → `%40`). Workflow-ът *Migrate* (Actions → Run workflow) пуска миграциите и по желание прави регистриран потребител администратор.
